# Glossário

Termos explicados de forma simples. Cresce conforme os estudos avançam.

| Termo | O que é |
|---|---|
| **GRC** | Governança, Riscos e Compliance: tratar os três de forma integrada. |
| **Governança** | Como a direção define rumo, decide e acompanha os resultados. |
| **Gestão** | Como o rumo definido pela governança é planejado e executado no dia a dia. |
| **Compliance** | Estar em conformidade com obrigações externas (leis, contratos, regulador) e internas (políticas). |
| **Risco** | Efeito da incerteza nos objetivos: algo que pode acontecer e afetar a empresa. |
| **Política** | Documento que define regras e responsabilidades sobre um tema. Precisa de indicador e data de revisão. |
| **Indicador de efetividade** | Medida que mostra se uma política ou controle está funcionando na prática. |
| **Controle** | Ação, processo ou ferramenta que reduz um risco. |
| **Framework** | Conjunto de boas práticas para organizar um tema (ex.: ITIL, COBIT, NIST CSF). |
| **Norma (ISO)** | Documento com requisitos reconhecidos internacionalmente; algumas permitem certificar a empresa. |
| **SGSI** | Sistema de Gestão de Segurança da Informação, o que a ISO/IEC 27001 pede para implantar. |
| **ITIL** | Framework de boas práticas de gestão de serviços de TI. |
| **COBIT** | Framework de governança e gestão de TI da ISACA. |
| **Incidente** | Interrupção ou queda de qualidade de um serviço que está acontecendo agora. |
| **Problema** | Causa, conhecida ou não, de um ou mais incidentes. |
| **Blameless** | Cultura de analisar falhas sem procurar culpados, para aprender e corrigir. |
| **Governança de dados** | Saber quais dados a empresa tem, onde estão, quem é dono e qual a qualidade. |
| **Governança de IA** | Regras, papéis e controles para usar IA de forma segura, ética e em conformidade. |
| **Framework de segurança** | Conjunto de diretrizes, controles, gestão e auditoria já testados, usado como "caixa de ferramentas". |
| **NIST CSF** | Framework de cibersegurança do NIST (EUA). Versão 2.0 com 6 funções: Governar, Identificar, Proteger, Detectar, Responder, Recuperar. |
| **CIS Controls** | 18 controles e 153 medidas do Center for Internet Security, em 3 grupos (IG1, IG2, IG3). |
| **IG1** | "Higiene básica" do CIS: 56 medidas mínimas para empresas pequenas. |
| **CID** | Confidencialidade, integridade e disponibilidade, a tríade da segurança da informação. |
| **PDCA** | Planejar, executar, checar e agir: ciclo de melhoria contínua das normas ISO. |
| **Escopo (ISO)** | A parte da empresa que entra no sistema de gestão e na certificação. |
| **SOC 2** | Relatório de auditoria (Tipo I ou II) sobre controles para dados de clientes, comum em empresas de nuvem. |
| **PCI DSS** | Padrão de segurança para quem armazena, processa ou transmite dados de cartão de pagamento. |
| **Shadow IT** | Tecnologia (apps, planilhas, SaaS) usada sem conhecimento ou aprovação da área responsável. |
| **SaaS** | Software como serviço: o sistema é usado pela internet, por assinatura, sem instalar nada. |
| **Make or buy** | Decisão de fazer internamente ou comprar/terceirizar, conforme desempenho e diferenciação. |
| **ISO/IEC 38500** | Norma de governança de TI: avaliar, dirigir e monitorar. Versão 2024 com 11 princípios (alinhada à ISO 37000). |
| **ISO/IEC 38505-1** | Aplicação da ISO 38500 à governança de dados. |
| **IT4IT** | Modelo do Open Group para gerir a TI como cadeia de valor, com 7 fluxos de valor na versão 3.0. |
| **DPBoK** | Digital Practitioner Body of Knowledge, do Open Group: como a TI amadurece de um time pequeno até a corporação. |
| **Serviço (ITIL 4)** | Meio de cocriar valor, facilitando os resultados que o consumidor quer sem que ele assuma custos e riscos específicos. |
| **Cocriação de valor** | O valor nasce da colaboração entre provedor e consumidor; os dois influenciam o resultado. |
| **Cliente / usuário / patrocinador** | Papéis do consumidor: quem define requisitos e responde pelo contrato / quem usa / quem autoriza e paga. |
| **Utilidade** | O que o serviço faz: se atende ao propósito (*fit for purpose*). |
| **Garantia** | Como o serviço entrega: disponibilidade, capacidade, segurança e continuidade (*fit for use*). |
| **Princípios orientadores** | 7 recomendações universais do ITIL, de "foco no valor" a "otimize e automatize". |
| **4 dimensões** | Organizações e pessoas; informação e tecnologia; parceiros e fornecedores; fluxos de valor e processos. |
| **PESTEL** | Fatores externos: político, econômico, social, tecnológico, legal e ambiental. |
| **POP** | Procedimento operacional padrão: passo a passo para todos executarem a tarefa do mesmo jeito. |
| **BANI** | Frágil, Ansioso, Não linear e Incompreensível: descrição do mundo atual, evolução do VUCA. |
| **Antifrágil** | Que não apenas resiste ao choque, mas melhora com ele (conceito de Nassim Taleb). |
| **OKR** | Objectives and Key Results: objetivo inspirador mais resultados-chave mensuráveis. |
| **Kaizen** | Melhoria contínua, base da cultura Lean. |
| **Backlog** | Lista priorizada de tudo que precisa ser feito. |
| **Sprint** | Ciclo curto de trabalho no Scrum, de 1 a 4 semanas. |
| **Kanban** | Quadro que torna o fluxo de trabalho visível, com limite de itens em andamento. |
| **Comunicação (processo)** | Só se completa quando o receptor entende e devolve um retorno; informação é apenas transmitir dados. |
| **Ruído e interferência** | Perturbações que deformam a mensagem: o ruído vem de dentro do sistema, a interferência vem do ambiente externo. |
| **Barreiras à comunicação** | Pessoais (emoções, valores), físicas (ambiente, distância) e semânticas (palavras e símbolos com sentidos diferentes). |
| **Escuta ativa** | Ouvir para compreender o ponto de vista do outro, sem preparar a resposta enquanto ele fala. |
| **Feedback** | Retorno sobre um comportamento, corretivo ou de reconhecimento: descrever, dizer a consequência, verificar, planejar e reconhecer. |
| **Comunicação de liderança** | Mensagem do líder ligada à cultura e aos valores, sobre visão, missão e ação, para fortalecer confiança e compromisso. |
| **Storytelling** | Contar histórias, com começo, meio e fim, personagens e conflito, para transmitir uma mensagem de forma memorável. |
| **DevOps** | Cultura que aproxima desenvolvimento e operação, com práticas e ferramentas para entregar software com velocidade e qualidade. |
| **Integração e entrega contínuas (CI/CD)** | Integrar e testar o código com frequência e manter o software sempre pronto para ser liberado. |
| **DevSecOps** | Segurança distribuída por todo o ciclo de desenvolvimento e operação, e não só no final. |
| **Lead time** | Tempo total desde o pedido até a entrega. |
| **Cycle time** | Tempo desde o início efetivo do trabalho até ficar pronto. |
| **WIP** | Work in progress: quantidade de trabalho em andamento ao mesmo tempo, limitada no Kanban. |
| **UML** | Linguagem de notação visual para modelar sistemas, sobretudo orientados a objetos. |
| **Caso de uso** | Funcionalidade do sistema vista do ponto de vista do usuário (ator), parte do modelo de requisitos funcionais. |
| **Shadow AI (IA na sombra)** | Uso de ferramentas de IA na organização sem inventário, dono nem avaliação, muitas vezes por contas pessoais. |
| **RAG** | Retrieval-Augmented Generation (busca aumentada): o modelo consulta uma base de documentos antes de responder. |
| **RIPD** | Relatório de Impacto à Proteção de Dados Pessoais, previsto na LGPD. |
| **RoPA** | Registro das atividades de tratamento de dados pessoais, com finalidades, bases legais e fluxos. |
| **MITRE AI Maturity Model** | Modelo público e gratuito de maturidade em IA: seis pilares, 20 dimensões e cinco níveis. |
